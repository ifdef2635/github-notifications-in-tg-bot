# GitHub Notifications in Telegram

Telegram-бот, который следит за дедлайнами открытых задач (issues) в репозитории GitHub и напоминает о них в Telegram: за 10, 5, 3, 2 и 1 день до срока, а после срока — ежедневно, пока задача не закрыта.

## Возможности

- Дедлайн берётся из **milestone** задачи или из текста задачи (`Дедлайн: 2025-04-15`).
- Если у задачи есть **assignee**, уведомление получает он (при привязанном GitHub-логине). Если assignee нет — все подписчики.
- Проверка раз в сутки в **9:00 UTC**.
- Pull request'ы игнорируются, учитываются только задачи.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | Подписаться на уведомления |
| `/setgithub <логин>` | Привязать GitHub-логин, чтобы получать уведомления по своим задачам |
| `/stop` | Отписаться и удалить привязку логина |

## Как это работает

Бот проверяет дедлайны и отправляет уведомления:

- **за 10, 5, 3, 2, 1 день** до дедлайна;
- **при просрочке** — ежедневно, пока задача открыта.

В день самого дедлайна уведомления нет.

```text
⏳ Задача "Реализовать API"
Осталось 3 дня до дедлайна
Ссылка: https://github.com/user/repo/issues/1
```

```text
🔴 Задача "Реализовать API"
Просрочена: 2 дня
Ссылка: https://github.com/user/repo/issues/1
```

### Откуда берётся дедлайн

1. Если у задачи есть milestone с датой (`due_on`) — берётся она.
2. Иначе дата ищется в теле задачи после слова `Дедлайн` или `Deadline` (регистр не важен):

   | Пример | Формат |
   |---|---|
   | `Дедлайн: 2025-04-08` | `ГГГГ-ММ-ДД` |
   | `Deadline: 2025.04.08` | `ГГГГ.ММ.ДД` |
   | `Дедлайн: 08/04/2025` | `ДД/ММ/ГГГГ` |
   | `Дедлайн 08-04-2025` | `ДД-ММ-ГГГГ` |

### Кому приходит уведомление

| Ситуация | Получатели |
|---|---|
| У задачи нет assignee | все подписчики (`/start`) |
| Есть assignee, логин привязан через `/setgithub` | эти assignee |
| Есть assignee, но ни у кого логин не привязан | никто (в лог пишется предупреждение) |

Логины GitHub сравниваются без учёта регистра. Один логин привязан к одному чату: новая привязка заменяет прежнюю.

## Установка и запуск

Требуется **Python 3.9+**.

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/ifdef2635/github-notifications-in-tg-bot.git
   cd github-notifications-in-tg-bot
   ```

2. Создайте виртуальное окружение (по желанию) и установите зависимости:
   ```bash
   python -m venv .venv
   source .venv/bin/activate  # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   ```

3. Создайте файл `.env` в корне проекта:
   ```ini
   GITHUB_TOKEN="github_pat_1234"
   TELEGRAM_TOKEN="1234:QWERTY"
   REPO_NAME="your_nick/repo_name"
   ```

   | Переменная | Описание |
   |---|---|
   | `GITHUB_TOKEN` | Токен GitHub с правом чтения задач репозитория (для fine-grained токена — `Issues: Read-only`) |
   | `TELEGRAM_TOKEN` | Токен бота от [@BotFather](https://t.me/BotFather) |
   | `REPO_NAME` | Репозиторий в виде `владелец/имя` |

   Если какая-то переменная не задана, бот сообщит об этом при запуске.

4. Запустите бота:
   ```bash
   python main.py
   ```

5. Откройте бота в Telegram и отправьте `/start`. Чтобы получать только свои задачи, затем `/setgithub ваш_логин`.

Подписчики хранятся в файле `users.db` (SQLite) в папке запуска. Он создаётся автоматически и не попадает в git.

## Структура проекта

| Файл | Назначение |
|---|---|
| `main.py` | Запуск бота и ежедневного планировщика (APScheduler) |
| `bot_handlers.py` | Команды `/start`, `/stop`, `/setgithub`, отправка сообщений |
| `notifications.py` | Проверка дедлайнов, тексты уведомлений, выбор получателей |
| `github_handler.py` | Получение задач из GitHub (кэш на 5 минут) и разбор дедлайнов |
| `database.py` | SQLite: подписчики и привязка GitHub-логинов |
| `config.py` | Переменные окружения и клиент GitHub |
| `tests/` | Тесты |

## Отладка и тесты

- `CHECK_ON_START=1 python main.py` — проверить дедлайны сразу при запуске. По умолчанию проверка идёт только в 9:00 UTC.
- Тесты: `python -m unittest discover -s tests`.
